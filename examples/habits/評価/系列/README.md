## 実行方法（評議会レベル検証は novel-council-layer 内の新セッション必須）

評価は書き手レイヤーと切り離すため、**`novel-council-layer` 内の新セッション**で実行する。

1. `cd "/Users/user/AI創作工房/novel-council-layer"` → `claude`（新セッション）
2. [`../起動カード_本文_系列.md`](../起動カード_本文_系列.md) の枠内をコピーして貼る（**貼るものは、同紙の 62〜108行である**）。

```

```

### ⚠ この回だけ、方式を一つ変えた——複数回の Read を許す

**`skills/story-council/SKILL.md` は「本文を評価者のプロンプトにインラインで渡す」と指示している。** **本件ではこれを行わない**（**設計評価の五単位と同じ逸脱である**——**入力が大きすぎて、インラインで渡すと議長の文脈が破綻する**）。**代わりに、評価者には `input.md` の絶対パスを渡して Read させる。**

**⚠ さらに、この回だけ、評価者に*複数回*の Read を明示的に許した。** **Read は既定で2,000行までしか返さず、この入力は 37,405行ある**——**一度の Read では、六十三話のうち最初の数話しか入らない**。**前の四巻の回は「この Read だけにせよ」と書いたが、この回は行数が桁違いであるため、方式を変えた。**

**⚠ ゆえに、走ったあとに確かめるべきことが一つ増える**——**各評価者の `content_summary` に、読み残しの申告が無いことである**（**→ 下の「申し送り」**）。

## 評議会に渡す文脈（`context`）——決定リストは渡さない

事実だけを一行渡す（**設計評価の五単位と同じ規則である**）。

> これは連作小説の、四巻六十三話の本文を、巻一から巻四へ番号順に連結したものである。各話には、名の書かれた紙と、扱う癖と、一拍が、一つずつ置かれる。四巻は、それぞれ別の語り手が語る。四巻を、一つの連作として読んで評価してよい。入力は大きい。読み残しがあれば、その旨を content_summary に書くこと。

**決定リスト・禁則・触れない三つの規則は渡さない。** **渡せば評議会は「適合検査器」になり、それは既に書き手側が機械的にやっている**（**場面表の不変条件の検算**）。**外部の目に価値があるのは*何も知らない読み*のほうである。**

> **⚠ `?` についての一行は、この回は渡していない。** **設計評価の五単位では「`?` は著者が意図的に未決定として残した印であり、欠落ではない」を渡した**（[`../README.md`](../README.md)——**渡さないと、六十三話すべてで「話末の引きが未設計」という同趣旨の所見が並び、報告がそれで埋まるため**）。**⚠ 本文の回は、これを渡していない**（**ゆえに `?` を閉じる方向の提案が、生のまま出る**——**→ 下の「担当外」**）。

## ループ

評価 → `revision_direction`（次回の修正方向）→ **反映** → 再評価 → `compare_reports.py` で差分。

**評議会は書き換え指示を出さない。** 材料（`weaknesses`・`improvement_suggestions`・`expected_disagreement_points`）を出すだけである。**反映は書き手側が行い、所見を A（決定に触れる＝動かさない）／B（設計内部の不整合＝書き手が直す）／C（著者が決める）／D（この評価の読み方）に仕分ける。**（[`../進捗.md`](../進捗.md) §2）
