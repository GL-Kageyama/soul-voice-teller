## 4. 実測の記録（済んだことの根拠）

- **連結の検算**——五入力とも、出典の区切りマーカーの数と出典一覧の行数と実際の出典数が一致した（巻一16・巻二17・巻三18・巻四20・系列2）。各話の場面表の数も実ファイル数と一致（14・15・16・18）。五入力とも非空。
- **起動カードの検算**——`args:` の行が5、`出力先:` の行が5。順序は 巻一→巻二→巻三→巻四→系列。`content` のパスが五つとも、その単位の `input-anonymized.md` を正しく指している。五つのファイルはどれも非空。
- **匿名化**——`utils/anonymize.py` に `--title "ハビッツ！！！"` と `--title "ハビッツ"` を渡して実行。**五つとも赤字0件**（`0 occurrence(s) redacted`）。`input-concept.md` と `input-anonymized.md` は**バイト単位で同一**。
  - 作品名は設計文書に一度も現れないので、**この入力では第一の盲は入力そのものが満たしている。**著者名・作者名の記載も無い。
  - 巻題（例：四『書いていない名』）は**匿名化していない**。設計の本文が33箇所で参照している構造の名であり、消せば意味が壊れる。**作品名ではなく中身の名である。**
- **五報告の検算**——`utils/validate_output.py --json` は**五報告とも `valid: true`**（`kind: "council report"`）。招集は五つとも10体、未招集は五つとも `prose-style` / `narrative-technique` / `reader-experience` の3体、**除外は五つとも0体**（Phase 2.5 の再試行は一度も発生していない。50体の個別報告がどれも一発で `valid: true`）。
- **`content_summary` の検算**——50体すべてが、その単位の中身を指す具体的な要約を持っていた（**90〜260字**、同一報告内で重複なし）。空の要約も定型の要約も無い。**これが Read の効いたことの根拠である**（要約が空なら Read が通っていない）。
- **`mode: full` の分散**——各次元を採点するのは単一の評価者なので、**per-dimension variance は構造的に 0** になる。五報告とも `disagreement_map` は分散からではなく、各評価者の `expected_disagreement_points` と本文から編集した。**`render_report.py` は `disagreement_map` を「不一致なし」と表示するので、実質的な不一致は JSON を直接読むこと。**（この一件は五報告とも `caveats` に記録済み。）
