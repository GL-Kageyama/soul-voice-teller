## ⚠️ 注意点

- 【評価者の起動方法の逸脱】評価者定義（~/.claude/agents/*-ja.md）は frontmatter に `tools: []` を持ち、直接起動すると十三名すべてが `tool_uses: 0` で落ちる。本実行では一名につき general-purpose のラッパーを一つ起動し、その中で評価者定義ファイルと本文の絶対パスを Read させ、評価者として JSON を出させた。したがって「評価者エージェントを直接起動した」のではなく「評価者の定義を読んだ汎用エージェントが評価者として振る舞った」。この逸脱は十三名に等しく掛かっている。
- 【議長の文脈に本文を読み込んでいない】content は本文そのものではなく絶対パスで渡した。議長（この記録を書いている側）は本文を一度も通読していない。ゆえに本文の細部についての議長の判断は、評価者の引用を通したものであり、議長自身の読解ではない。
- 【full mode の構造的限界】十三名を招集したが、各次元を採点したのは各一名である。したがって story_vector の per-dimension 分散はすべて 0 であり、これは「一致」ではなく「測っていない」を意味する。disagreement_map は分散の閾値（100/400）によってではなく、評価者間で実際に割れた読みと expected_disagreement_points に基づいて構成し、variance フィールドは null とした（0 と書けば「一致」の意味になるため）。
- 【不合格の再生成】reader-experience の一度目の出力は JSON の構文エラーで落ちた——`strengths` 配列を閉じた直後に余分な `}` があり、そこでオブジェクトが閉じ、続く `,"weaknesses":[...` が余分なデータになっていた。手で直さず、同じ評価者を再起動して再生成した（Phase 2.5）。二度目は一発で通った。除外された評価者はゼロである。
- 【評価者は設計を知らない】十三名に渡したのは本文ファイルの絶対パスと、content_type・domain・context だけである。design.md・話割り.md・各話の場面表・台帳・内面の規律・進捗表は一名にも渡していない。ゆえに「`?` が閉じていない」「内面が書かれない」「会話がない話がある」「いちばん下の一枚が開かれない」という指摘は、それが設計上の決定であることを知らない側からの所見でありうる。この但し書きは report.json の内容を訂正しない——revision_direction は評価の記録としてそのまま残し、訂正は所見側に書く。
- 【単位の切り方】この評価は十五話を一つの本文として読んだ。巻単位の評価はこれが初めてである。第九話と第十話は既に単話で同じ評議会を通っており（評価/02-09_一枚だけ/・評価/02-10_四枚目/）、同じ指摘が再出するかは数値の大小ではなく指摘の一致で見ること。
