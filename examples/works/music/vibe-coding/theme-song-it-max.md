# theme-song —— 主題歌一式（Suno 用・PC内部状態版）／『バイブコーディングの揺れ方 — 内部状態の揺れ方 —』

> 出所: [`theme-song.md`](theme-song.md) と同じ作品の、**語彙の極限版**。**題材・事実・出所・音・声・置き場は動かさない。** 変えたのは、**歌詞の文法**である。
>
> **この版の賭け**: **歌の大半を、PCの内部状態だけで作る。** CPU、クロック、ファン、メモリ、ページキャッシュ、ヒープ、スワップ、ファイルディスクリプタ、ソケット、割り込み、コンテキストスイッチ、ロードアベレージ、温度——**機械の内側の天気が、歌の文法になる。** **それでもテーマはバイブコーディングである。** 人間は、マイクに向かって話し、生成されたコードを読まず、デプロイし、朝に「わからない」と言う。**機械の状態が、その人間の状態を映す。**
>
> ⚠ **これは、部屋の内側向けの版である。** 用語を知らない聴き手には、意味が届かない。**一般向けは [`theme-song.md`](theme-song.md)、物語寄りのIT版は [`theme-song-it.md`](theme-song-it.md)。** **Suno には、一度に一版だけ渡す。**

## 1. 曲名

**『バイブコーディングの揺れ方』**
**— 内部状態の揺れ方 —**

- **題は動かさない。** 依頼された題が、この歌の入口である。
- **副題は「内部状態」。** 歌の場所を、最初に**機械の内側**で言う。base 版が**部屋の歌**なら、この版は**部屋の中の、もっと内側の歌**である。
- **題だけが、IT用語でない。** 「バイブコーディング」は概念の名、「揺れ方」は情景の語である。**歌の本体は機械の状態で、題だけが人間の言葉**——この非対称が、この版の性格である。

### 歌詞の作法（PC内部状態版）

- **Aメロは、機械の朝である。** CPU がアイドルで、クロックが低く、ファンが低速——**まだ、何も起きていない。** そこへ**プロンプトとマイクの入力**が入り、**ディフを読まないまま、アクセプトオール**——**モデルが推論し、GPU が発熱し、消費電力が上がり、ファンが全開になる。** **人間の短い言葉が、機械の温度を変える。**
- **前サビは、バイブコーディングのパイプラインである。** 読み込み、推論、生成、適用、デプロイ、ロールバック、デプロイ——**七つの工程が、七拍で流れる。** **これは、機械の内部でもあり、人間のやり方でもある。** 「それだけ」で切る。
- **サビは、用語と人間の混成である。** 「設計 保守 SLO／可用性 冪等性」——**知らない実践の名前**を並べ、**「知らないぜ」**で落とす。**題の「揺れ方」とフックの「揺らしてる だけ」だけが、人間の言葉**である。
- **Bメロは、機械の悲鳴である。** ヒープが膨れ、ページフォールトが増え、スワップに入り、ディスク I/O を待ち、ファイルディスクリプタとソケットが枯れる。**500 が返り、リトライがでたらめになり、無限ループが消え、割り込みとコンテキストスイッチが多発し、ロードアベレージが上がり、ファンが全開になり、温度が上限に達し、サーマルスロットリングが始まる。** ⚠ **最後の「ヒープ おれの 背 越える」だけが、身体である。** **機械の内側が、人間の背に重なる。**
- **ブレイクダウンは、動詞の無い壁である。** 十四の**PC内部の失敗名**を、**名前だけで**置く。⚠ **意味を歌わない。説明を歌わない。** **名前が、そのまま打楽器になる。** **「デッドロック」の四拍、「セグメンテーションフォールト」の八拍——語の長さが、リズムを決める。**
- **ブリッジは、プロセステーブルである。** プロトタイプ、月曜本番、プロセス一覧、知らない PID、デーモン稼働、親 PID 不明、開いたファイルディスクリプタ、開いたソケット、環境変数の鍵、露出した .env、無効な RLS、アクセプトオール、閲覧したログ、他人名義、所有不明——**最後に「わからない」だけが、人間の言葉**である。**機械は、全部知っている。** **人間だけが、知らない。**
- **アウトロは、明け方の機械である。** 朝五時、ファンは回り、スリープしない。オンコール、ポストモーテムは後日、コードを開く。**「揺れ方 不明」は報告書の語、「まだ 知らない」は人の語。** **同じことを、二つの言語で言う。**
- **反転は一語だけ。** 「揺らしてる だけ」→「揺らされて いる」。**base 版と同じ。** **用語を極限まで増やしても、歌の背骨は変えない。**
- **人間の行は、一節に一つだけ。** Aメロの「おれは 読まない」、前サビの「それだけ」、サビの「知らないぜ」、Bメロの「ヒープ おれの 背 越える」、ブリッジの「わからない」、アウトロの「まだ 知らない」。⚠ **用語の壁の中に、人間の窓が一つだけ開いている。**
- **用語は、すべて実在する。** ⚠ **造語しない。** **「それっぽい技術語」を作らない。** **実在の状態名・実在の失敗名だけを使う。** **だから、聴き手は意味を説明されなくても、名前の重さだけで受け取れる。**
- **テーマは、バイブコーディングである。** ⚠ **PCの内部状態は、テーマの代わりではない。** **テーマの material（素材）である。** **人間が話し、モデルが書き、コードが走り、機械が熱を持つ。** **その熱が、この歌である。**


⚠ **音は base 版から動かさない。** 変えたのは、**歌詞の文法と、声の運び**だけ。**同じ 107 bpm、同じ三ピース、同じ細い声。** **用語が主役になっても、バンドは人間のまま**——**その対比が、この版の音である。**

### なぜこの音か

- **歌詞が機械的になるほど、バンドは生々しくする。** ⚠ **用語を打ち込むなら、音まで打ち込みにしない。** **ギターの歪み、ベースの唸り、ドラムの開いたハイハット**が、**報告書を人間の歌に戻す。**
- **声は、固有名詞を使わずに記述する。** ⚠ **「あの人の声」と書かない。** **細い・高い・甘い・掠れた・鼻にかかる・張り上げない・ビブラートなし・舌足らず・拍の後ろ——声質と癖だけで、想起させる。** **名前は、音の外に置く。**
- **三つの楽器を、前へ出す。** **リードギターは、歌うように。** **ベースは、リズムを刻みながら、歌う。** **ドラムは、情熱的に。** ⚠ **ただし、どれも固有名詞では書かない。** **音の働きだけを書く。**
- **Aメロは、ほぼ語り。** 名詞を並べるので、**メロディを付けすぎると、言葉が潰れる。** **一語ずつ、平らに置く。** **サビでだけ、開く。**
- **ブレイクダウンは、叫ばない。** 十四の失敗名を、**事務的に、早口で**。**叫ぶと、怒りの歌になる。** **この歌は、怒っていない。** **報告しているだけである。**
- **最後のサビは、大きくしない。** 用語を全部着たあとの「揺らされて いる」は、**疲れている。** **悟っていない。**
- **長さの目安: 歌う行 115行、107 bpm・4/4 で、約4分15秒。** Suno の長さは **245–275 秒**を目安にする（推定）。⚠ **これは実測ではなく、行数からの見積もりである。** **ブレイクダウンの行は短いので、実際はもう少し短い可能性がある。**

## 5. 楽曲説明（Song Description）

```
A night inside the machine, told almost entirely in its internal state.
The computer wakes at two in the morning: CPU idle, clock low, fan slow,
memory half full, page cache cold. Then a prompt is entered, a microphone
opens, a model infers, the GPU heats, power draw rises, the fan goes to
full. The only plain sentence in the first verse is "I don't read it."

The pre-chorus is the vibe-coding pipeline: read, infer, generate, apply,
deploy, roll back, deploy. That is all. That is the whole method.

The chorus names the practices the narrator claims not to know — design,
maintenance, SLO, availability, idempotency — then admits it in plain
Japanese. The hook is the only human phrase in it: "I'm just swaying it.
My app. I'm just swaying it."

The second verse is the machine under load: heap swelling, page faults
rising, swap entered, disk I/O waits, file descriptors exhausted, sockets
exhausted, a 500 returned, random retries, an infinite loop gone,
interrupts and context switches multiplying, load average climbing, fan
at full, temperature at the limit, thermal throttling. The last line is
"the heap crosses my back" — the only body in the verse.

After the guitar break, a breakdown names fourteen internal failures with
no verbs: deadlock, race condition, memory leak, stack overflow,
segmentation fault, TLB miss, thrashing, OOM, file descriptor exhaustion,
socket exhaustion, interrupt storm, context switch storm, thermal
throttling, kernel panic. The names are the rhythm.

The bridge is the process table: prototype, Monday production, process
list, unknown PID, a daemon running, parent PID unknown, open file
descriptors, open sockets, the key in an environment variable, the .env
exposed, RLS disabled, Accept All, logs viewed, someone else's name,
ownership unknown. The only plain line is "I don't know." The machine
knows everything; the human knows nothing.

At five in the morning, the fan is still running; the machine will not
sleep. On-call. The postmortem is postponed. The code is opened. The way
it sways is unknown. "I still don't know."

The music is a mid-tempo garage rock sway: thin high sweet-and-hoarse
voice, nasal and cracked, no vibrato, sneering and playful, slurred and
behind the beat, mostly spoken. Lead guitar forward with twangy
hollow-body tone, melodic bends and jagged single-note riffs. Rhythmic
overdriven bass, syncopated and driving. Passionate hard-hit drums, open
hi-hat, rolling fills, crashing cymbals. No gang vocals, no shouting. The
terms are not explained. The last word is plain.
```

- 物語の何を歌うか（開示の頂の手前で）: **人間の一語で機械が熱を持ち、ヒープが膨れ、スワップに入り、FD とソケットが枯れ、見知らぬ PID のデーモンが走り、.env が露出し、RLS が無効のまま、朝五時までファンが回る。** **「所有 不明」で止まる。**

## 6. 挿入位置・使用意図

- **本命: エンジニアの内側の場——ハッカソン、勉強会、インシデントレビューの締め。** **用語が通じる部屋でこそ、この版は笑える。** **笑ったあとに、[Breakdown] と [Bridge] で黙る。**
- **base 版との住み分け。** base 版は**一般向け**。この版は**部屋の内側向け**——**用語を知っている者だけが、最初の笑いどころを知る。** **知らない者には、呪文に聞こえる。** **それも、この版の正しさである。**
- **製品のプロモーションには使わない。** ⚠ **この歌は、売り文句でも、警告でもない。**
- **セキュリティ研修のBGMにもしない。** ⚠ **この歌は誰も責めない。** **責める歌にすると、「わからない」が消える。**
- **短尺は、[Breakdown]＋[Bridge]＋[Outro]。** **十四の失敗名、プロセステーブル、明け方の機械**が、そのまま**事故のあらまし**になる。⚠ **用語を知らない聴き手には届かない。** **短尺の宛先を選ぶ。**

## 歌の検品（四則）

**一・嘘をつかずに歌う。**
歌詞の機構は、すべて一次資料の範囲である——声で話す、キーボードをほとんど触らない、読まない、全部受け取る、エラーをそのまま貼る、でたらめに頼む、コードが理解を超えて育つ、週末の使い捨てのつもり。`[S]` **CPU、クロック、ファン、メモリ、ページキャッシュ、プロンプト、マイク、モデル、推論、GPU、消費電力、ヒープ、ページフォールト、スワップ、ディスク I/O、ファイルディスクリプタ、ソケット、割り込み、コンテキストスイッチ、ロードアベレージ、温度、サーマルスロットリング、プロセス、PID、デーモン、環境変数、.env、RLS、ログ、オンコール、ポストモーテム、およびブレイクダウンの十四の失敗名は、実在の語と実在の状態**である `[S]`。**「環境変数 鍵／.env 露出／RLS 無効」は、脆弱性の一般形**であって、**特定の事件ではない** `[私]`。**歌い手は合成された非エンジニア**であり、**実在の誰かの経歴ではない** `[私]`。**統計は歌わない。**

**二・届けるものを約束する。**
