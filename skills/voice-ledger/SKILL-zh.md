# voice-ledger —— 灵魂之声的声音库（存储＋回读）

## 语言模式

本技能默认以英文写作。如需以其他语言写作，请传入 `lang` 参数（例如 `/voice-ledger lang=zh`）或在环境中设置 `SOUL_VOICE_TELLER_LANG=zh`。解析顺序：`$ARGUMENTS.lang` > `SOUL_VOICE_TELLER_LANG` > `en`。

- `en`（默认）：使用 `SKILL.md` 与 `../references/*.md`。
- `ja`：读取 `SKILL-ja.md` 与 `../references/ja/*.md`；以日语输出。
- `zh`：读取本文件（`SKILL-zh.md`）与 `../references/zh/*.md`；以中文输出。

所有输出均以解析出的语言书写。

## 技能元数据

- **id**：`voice-ledger`
- **version**：`0.1.0`
- **category**：`writing`（写作者层 · 持久）
- **standalone**：`true`
- **language**：`zh`（镜像于 `SKILL.md`（en）/ `SKILL-ja.md`）

## 定位

三层模型中**写作者层**的第二个技能。writer-persona「定下声音」（现在式设定）；本技能「存储声音」（过去式日记）。跨作品积累内省中听见的声音，并回读。

**与 persona 的区别**：persona 是「我这样写」，声音库是「我这样写过」。**不同文件。**

## 输入约定

- **存储时**：声音（五种）· 其来源 · 其语境。经 argument-hint 或对谈接收。
- **回读时**：回读的目的（构思开端 / 更新 persona / 卡壳 / fast-draft 干涸）。
- **保存位置**：`${SOUL_VOICE_HOME:-$HOME/.soul-voice-teller}/voice-ledger.md`

## 存储（五种声音）

| 种类 | 来源 | 例 |
|---|---|---|
| 构思之声 | B 问句 · 一闪 | 听见「这素材如此回应我反复书写的问句」的片段 |
| 草稿之声 | C 问句 · 偏离的记录 | 人物离开计划、开始自己动之处 · 其台词 |
| 书写起飞的瞬间 | 文思 | 涌现发生的条件（素材 · 约束 · 留白）。记录**条件本身**，作为复现的线索 |
| 触及禁忌的瞬间 | A-4 | 差点破坏 · 破坏了。是成了深度还是破坏 |
| 评价的共鸣 | 读者反应 | 外部评价中什么共鸣了 · 什么没有。只留声音，不被裹挟 |

**何时存储（诱发而非强迫）**：只在听见声音时。什么都没听见的日子，不硬挤一句；不添空行。

**一则的形式**（[../references/zh/声音.md](../references/zh/声音.md)）：

| 字段 | 内容 |
|---|---|
| 日期 · 作品 · 场景 | 何时 · 在哪部作品 · 在哪里听见 |
| 听见的声音 | **照原文。不概括——概括中声音会死** |
| 语境（回答了哪个问句） | 引用问句形式（A／B／C），以便同一问句能再次唤起它 |
| 已用／未用 | 供日后串联的标记 |

```markdown
- [x] 2026-08-14 / 《夜里行走的人》 / 第 2 章 · 高潮台词
  voice：这个男人不是「不道歉」——他是「无法道歉」。因为一道歉，某种东西就结束了。
  context：C-1（这句台词来自计划的要求，还是来自人物自身？）
  used：第 2 章的高潮。评价的共鸣也在此（originality 很高）。
```

## 回读（不只停在存储）

声音库不只为了存储，还为了**回读**。从不回读的 ledger 会沦为垃圾场。

- **构思开端**（premise 的 B 问句）——把前作的声音唤入新的问句
- **更新 writer-persona 时**——把积累的声音读作「灵魂故事走向了何处」，修订设定
- **卡壳时**——写不出时的水源
- **fast-draft 干涸时**（C-4，听不见 → 退回照着计划写）——退回之前，先听声音库

## 步骤

1. 确认「store」还是「read」（经 argument-hint 或对谈）。
2. **存储**：接收声音，判断它属于五种中的哪一种，以一则形式追加到 `voice-ledger.md`。声音**照原文**保留，且始终附上语境（哪个问句）。
3. **回读**：为这个目的重读声音库，引用相关的声音，作为更新材料 · 构思的来源 · 水源呈现。

## 注意

- **声音库本身不作判断**——它只存储、回读。「什么算声音」的选择由发问技能（persona / premise / fast-draft）来做。
- 灵魂故事与声音是**人（用户）之物**。AI 是反映 · 存储 · 归还它们的镜子，不是作者。
- 存储评价的共鸣时，**不要被外部评价裹挟**——不抄分数或结论；只留与你有共鸣的「声音」。
