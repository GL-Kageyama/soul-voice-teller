# character-forge —— 人物設計（欲求・傷・弧・声を作る）

## Skill Metadata

- **id**: `character-forge`
- **version**: `0.1.0`
- **category**: `writing`（構想層・任意下準備）
- **standalone**: `true`
- **language**: `ja`

## 位置づけ

任意下準備（技術目録 §2-A 人物の設計）。plot-design の「人物」欄（空欄可）を、fast-draft が「この人物らしく動かせる」粒度まで深める。無くても書けるが、人物が「役割（主人公・敵役）」でなく「生きている人間」になるかはここで決まる。

**出所**: 技術目録 §2-A（2-1〜2-16）。

## 入力契約

- **design.md**: `<作業ディレクトリ>/design.md`（人物欄。空欄・`?` でもよい）。
- **premise.md**: `<作業ディレクトリ>/premise.md`（核心の問い・テーマ——人物の欲求・傷はテーマと結びつく）。
- **persona**: `${SOUL_VOICE_HOME:-$HOME/.soul-voice-teller}/persona.md`（題材の嗜好・惹かれる人物と関係）。

## 手順

1. design.md の「人物」欄、premise のテーマ、persona の「題材の嗜好」を読む。
2. 人物ごとに「核」を確定する（§2-A）:
   - **欲求・目的（2-3）**: 何を欲するか（表面的な願い）
   - **動機（2-4）**: なぜ欲するか（根の部分）
   - **欠乏・傷・弱点（2-5）**: 内面の欠け・過去の傷
   - **信念・価値観（2-6）**: 何を正しいとするか・死守するもの
   - **声（2-13）**: 話し方・語彙・思考の癖。他者と区別される
   - **変化弧（2-12）**: どう変わるか／変わらないか
   - **表と内のずれ（2-16）**: 見た目・言動と内面の食い違い
2b. 人物の**ロール**を確定する——物語の中でその人物が何を*為す*か（ロールの無い人物は動かない。核だけでは静止したまま）:
    - **賭け**（失い得るもの）: 物語の因果に結びついた欲求・傷（例「正体を隠して得た居場所——告白で失われる」）
    - **挑戦**（立ち向かうもの）: 2つの要素——そして能動の動詞の主語は常に**主人公**であり、敵ではない:
        1. **敵（名指し）**: 何に・誰に立ち向かうか。名指す（曖昧な「組織」ではなく、敵役を）。
        2. **敵の抵抗（応答・段階的）**: 主人公の追及が深まるほど、敵の抵抗が段階的に迫る——制止 → 拒否 → 威圧 → 最終対峙。この抵抗は、主人公の追及への**応答**であり、敵自身の能動的な仕掛けではない。最終対峙はクライマックス（追及の到達点）に置き、中盤に置かない。
        主人公の追及そのもの（調べる・暴く・突きつける）は、能動の原理とシーン表が担い、ここに書かない。敵を能動の主語にしない（「敵が圧力をかける」と書かない）——それは主人公を「圧力への応答」に転化させ、自律性を崩す（V6 で -6/-24/-10 を実測）。
    - **能動の原理**（ルール）: 「Xのために動く。Xが脅かされればYを為す。XのためならZを犠牲にできる」。Z（リスクテイク）が賭けの実在の試金石——何を犠牲にできるか言えなければ、賭けは実際には掛かっていない。この反応（Y）が*らしさ（一貫性）*の種——一つの Y が、どの場面でも同じであること。
    注: 機能（主人公／敵役／…）は plot-design が因果の網から定める。賭けと能動の原理は、欲求・傷からあなた（character-forge）が定める。両者は賭けで交わる。*らしさ*はここで設定する値ではない——その一つの反応が場面をまたいで一貫することで生まれる結果であり、場面レベルで character-in-action が検証する。
3. **内面葛藤を1つに絞る**: 二つの相反する欲求・信念がぶつかる点（例: 守りたい vs 逃げたい）。これは変化弧の原動力。
4. 人物がテーマ（premise の核心の問い）とどう結びつくかを明記する——人物はテーマの「生きている議論」であるべき。
5. design.md の「人物」欄に書き込む。未定は `?` のまま残してよい（下準備は空欄を許す）。

## 出力

design.md の「人物」欄の詳細化（欲求・動機・傷・信念・声・変化弧・内面葛藤・表と内のずれ）。

## 注意

- **欲求に一貫性を持たせる**（2-3〜2-4）: 表面的な願い（欲求）と根の部分（動機）が食い違わない。食い違うなら、それが内面葛藤。
- 人物は「役割（2-11）」でなく「人」として作る。主人公・敵役は機能であり、その下に傷・欲求・信念がある。
- 敵役も**一方的な悪にしない**（2-27）: 敵の論理の正しさを持たせる。
- 声は persona の「禁じ手」に反しない範囲で。禁じ手に触れる人物は、理由を持って作る。
- **人物はフックの器である**。ここで定める欲求・傷は、読者が得る（寄り添う）もの。フックのエンジン（[../references/ja/フックのエンジン.md](../references/ja/フックのエンジン.md)）がそれを欠けさせる。与えられ、そして欠けさせられるものを人物に作る。
- 人物の真のロールが隠れているなら（表のロール→隠れたロール。例: 見かけは味方、実際は敵役）、核の層に留めない。design.md の「伏線」欄を**伏線マップ**として埋める:
    - 表のロール → 隠れたロール
    - 誰から隠すか（読者＝どんでん返し／他の人物＝皮肉）
    - 幹の問い（「この人物は本当は誰か」）
    - 開示（転機）と、その開示が開く次の問い
    - 伏線一覧: 場面・手がかり（答えでなく食い違い）・開示度（0→1、単調）・開示曲線（読者／他の人物）・回収（どの開示がそれを回収するか）
  このマップ無き隠れたロールは、根拠のないどんでん返し（手がかりの無い開示）になる。
