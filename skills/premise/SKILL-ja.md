# premise —— 発想（persona＋ため庫に照らして作品の入口を決める）

## Skill Metadata

- **id**: `premise`
- **version**: `0.1.0`
- **category**: `writing`（構想層・作品ごと）
- **standalone**: `true`
- **language**: `ja`

## 位置づけ

三層モデルの**構想層**の前段。`inspire`（発想）はここに統合されている——B問いが発想そのもの。作品ごとに、魂の物語（persona）に照らしてテーマ・ログラインを選ぶ。

**入力契約（明文化）**: `人間の種（何を書きたいか） ＋ persona（この人間の嗜好） ＋ voice-ledger（過去の声）`。

## 入力契約

- **種**: ユーザーの書きたい素材・題材の断片。argument-hint または対話で受け取る。無ければ対話で引き出す。
- **persona**: `${SOUL_VOICE_HOME:-$HOME/.soul-voice-teller}/persona.md`。**必須**。無ければ writer-persona を先に促す。
- **voice-ledger**: `${SOUL_VOICE_HOME:-$HOME/.soul-voice-teller}/voice-ledger.md`。あれば読む（前の作品の声を新しい問いに呼び込む）。無くてもよい。

## 手順

1. 種・persona・ため庫を読み込む。persona が無ければ writer-persona を促して中断する。
2. B問い（[../references/ja/内省問い.md](../references/ja/内省問い.md) B章）で発想する。ground = **persona＋ため庫**。ただし persona は温度の違う2層に分けて使う:
   - **魂の声（HOW）＝魂の物語・美意識・声・禁じ手** → 低温度で照合（忠実に守る）
   - **題材の嗜好（WHAT）＝A-5** → 高温度で着想（種として使う。引き寄せすぎない）
   - **B-1 テーマ**——この素材は書き手の「何度も書き続ける問い」にどう応えるか
   - **B-2 ログライン**——この物語を書き手の声で言うとどう鳴るか（要約でなく核を一言で）
   - **B-3 人物・世界**——書き手が最も書きたくなる人物・惹かれる場所はどこか
   - **B-4 種×題材の揺らぎ**——種の季節・舞台・時間帯・人物・関係が persona の題材（A-5）と重なりすぎたら意識的にずらす。食い違い（例：夏のお盆と秋の嗜好）は揺らぎとして歓迎し、意図した逸脱は `?` で記録する
3. 発想の結果を、下の出力形式にまとめる。**「誰でも書ける」答え**（紋切り型のテーマ・ログライン）は捨てて、声・美意識（HOW）には引き寄せ直す。題材（WHAT）は persona の嗜好と重なりすぎたら意識的に離す——毎回同じ題材になるのは凡庸。
4. **読者像と読者への約束**を必ず定める（小説は「読まれる時間の芸術」）。誰に・どんな約束をするかを書かない限り、草稿は読者を持たない。約束には**反応軸**を含める——6軸のうち主軸・副軸を名指す（[../references/ja/6つの反応軸.md](../references/ja/6つの反応軸.md)）。
5. 出力を `<作業ディレクトリ>/premise.md` に保存する。作業ディレクトリはユーザーが指定（未指定なら `examples/<スラッグ>/`）。

## 出力

`<作業ディレクトリ>/premise.md`

```markdown
# premise —— 作品の入口

## ログライン
（この物語を一言で。書き手の声で鳴らした核）

## 核心の問い
（この物語が問う、決着のついていない問い。persona の魂の物語と照らす）

## テーマ
（persona の「何度も書き続ける問い」にどう応えるか）

## ジャンルの約束
（読者がこの作品に期待してよいこと）

## 反応軸
（6軸のうち主軸・副軸——読者が主に感じる反応。例：恐怖が主・感嘆が副）

## 文体の方向
（persona の声・筆致に照らした、この作品の文の方向）

## 読者像と読者への約束
（誰に読ませるか・その読者にどんな体験を約束するか）
```

## 注意

- 発想は**照合と揺らぎの両方**。声・美意識・禁じ手（HOW）は ground（persona）に照合して守る。題材の嗜好（WHAT）は種として使うが引き寄せすぎない——重なりすぎたら意識的に離れる（高温度の揺らぎ）。どちらにせよ「それらしいテーマ」を ground からでっち上げない。
- 読者像と約束は**必須**（構想レビュー flash #1）。省略してはならない。
- ここでは設計しない（因果構造・シーン表は plot-design の仕事）。premise は「何を問い・どんな文で・誰に読ませるか」を定めるまで。
- **約束が反応軸を選ぶ**。読者がどの軸を感じるか（6軸）は、ジャンルの約束＋読者像と約束の一部としてここで定める（[../references/ja/6つの反応軸.md](../references/ja/6つの反応軸.md)）。plot-design がその軸を全体の弧へ展開する。
- **核心の問いが幹である**。premise が定める決着のついていない問いは、作品全体のフック——頂まで温存される未知——である（[../references/ja/フックのエンジン.md](../references/ja/フックのエンジン.md)）。
