# premise —— 発想（persona＋ため庫に照らして作品の入口を決める）

## Skill Metadata

- **id**: `premise`
- **version**: `0.1.0`
- **category**: `writing`（構想層・作品ごと）
- **standalone**: `true`
- **language**: `ja`（本訳。en/zh は追いつき待ち）

## 位置づけ

三層モデルの**構想層**の前段。`inspire`（発想）はここに統合されている——B問いが発想そのもの。作品ごとに、魂の物語（persona）に照らしてテーマ・ログラインを選ぶ。

**入力契約（明文化）**: `人間の種（何を書きたいか） ＋ persona（この人間の嗜好） ＋ voice-ledger（過去の声）`。

## 入力契約

- **種**: ユーザーの書きたい素材・題材の断片。argument-hint または対話で受け取る。無ければ対話で引き出す。
- **persona**: `${SOUL_VOICE_HOME:-$HOME/.soul-voice-teller}/persona.md`。**必須**。無ければ writer-persona を先に促す。
- **voice-ledger**: `${SOUL_VOICE_HOME:-$HOME/.soul-voice-teller}/voice-ledger.md`。あれば読む（前の作品の声を新しい問いに呼び込む）。無くてもよい。

## 手順

1. 種・persona・ため庫を読み込む。persona が無ければ writer-persona を促して中断する。
2. B問い（[../references/内省問い.md](../references/内省問い.md) B章）で発想する。ground = **persona＋ため庫**——「この人間ならどう選ぶか」を照合する:
   - **B-1 テーマ**——この素材は書き手の「何度も書き続ける問い」にどう応えるか
   - **B-2 ログライン**——この物語を書き手の声で言うとどう鳴るか（要約でなく核を一言で）
   - **B-3 人物・世界**——書き手が最も書きたくなる人物・惹かれる場所はどこか
3. 照合の結果を、下の出力形式にまとめる。**「この人間なら」を離れた答え**（誰でも書けるテーマ・紋切り型のログライン）は捨てて、persona に引き寄せ直す。
4. **読者像と読者への約束**を必ず定める（小説は「読まれる時間の芸術」）。誰に・どんな約束をするかを書かない限り、草稿は読者を持たない。
5. 出力を `<作業ディレクトリ>/premise.md` に保存する。作業ディレクトリはユーザーが指定（未指定なら `examples/<スラッグ>/`）。

## 出力

`<作業ディレクトリ>/premise.md`

```markdown
# premise —— 作品の入口

## ログライン
（この物語を一言で。書き手の声で鳴らした核）

## 核心の問い
（この物語が問う、決着のついていない問い。persona の魂の物語と照らす）

## テーマ
（persona の「何度も書き続ける問い」にどう応えるか）

## ジャンルの約束
（読者がこの作品に期待してよいこと）

## 文体の方向
（persona の声・筆致に照らした、この作品の文の方向）

## 読者像と読者への約束
（誰に読ませるか・その読者にどんな体験を約束するか）
```

## 注意

- 発想は**照合**であって捏造でない。B問いの ground は persona＋ため庫。ground を離れて「それらしいテーマ」をでっち上げない。
- 読者像と約束は**必須**（構想レビュー flash #1）。省略してはならない。
- ここでは設計しない（因果構造・シーン表は plot-design の仕事）。premise は「何を問い・どんな文で・誰に読ませるか」を定めるまで。
