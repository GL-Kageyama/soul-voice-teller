# theme-song —— 把完成的作品凝缩为一首主题曲

## Skill Metadata

- **id**: `theme-song`
- **version**: `0.2.0`
- **category**: `delivery`（届ける · 主题曲）
- **standalone**: `true`
- **language**: `zh`

## 定位

三层模型的**送达**技能——package 之后的第二个。package 把完成的作品包装成读者能**接收**的样子，theme-song 把作品凝缩为一首歌，让灵魂**被听见**。其对照依据（ground）不是读者的第一印象（那是 package 的）——而是**作品的灵魂**：premise 定下的主题，以及 draft 中情感升起的场景。

**出处**: premise（主题 · 核心问句）＋流露与克制的美学（不道破源）。

## 输入契约

- **draft.md**: `<工作目录>/draft.md`（完成的作品——歌唱对象）。
- **premise.md**: `<工作目录>/premise.md`（主题 · 核心问句 · 约定——歌必须承载的东西）。
- **series-bible.md**: `<工作目录>/series-bible.md`（伏笔表 · 披露程度——什么不能唱）。
- **persona**: `${SOUL_VOICE_HOME:-$HOME/.soul-voice-teller}/persona.md`（声音 · 禁忌——歌用作品的声音唱）。
- **package.md**（可选）: `<工作目录>/package.md`——若已存在，曲名 · 副歌 · 曲风不得与标题 · 宣传语 · 简介矛盾。一个灵魂，两扇门。

## 依据的转向

package 对照读者的第一印象。歌对照**作品的灵魂**——主题，以及情感升起的场景。每个交付物（曲名 · 歌词 · 曲风 · 声乐 · 说明）都向那灵魂问同一个问题：*能否不点名、不剧透、且真正可唱地，承载这作品的灵魂？*

## 歌曲一套（六个交付物）

1. **曲名** — 歌之名。不取代作品的名字。与副歌重合的钩子。
2. **歌词** — 带结构标签（`[Intro]` / `[Verse 1]` / `[Chorus]` / `[Verse 2]` / `[Bridge]` / `[Outro]`）。守住流露与克制的五条，写成要被唱出来的诗行，而非被读的散文。
3. **曲风指定（Style of Music）** — 体裁 · 速度 · 情绪 · 时代 · 乐器，用音乐生成器易于解析的英语标签＋简短补充。不违背作品的约定。
4. **声乐指定** — 性别 · 音色 · 唱法。与作品的声音一致。
5. **歌曲说明（Song Description）** — 唱故事的什么（停在正体揭示之前）。给生成器的语境＋给人理解。
6. **位置与意图** — OP / ED / 插曲 / 片尾等，在故事整体中的角色。这正是「作品整体之歌」的根据。

## 歌曲的四则

1. **不撒谎地唱** — 歌词与曲风出自作品真实的主题与情感，不是作品会辜负的体裁承诺。安静的故事，不要套喧闹体裁的声音。
2. **承诺真正交付的** — 歌词与曲风承诺的情感，是作品真正交付的。给克制之物许诺宣泄爆发之歌，是违背的承诺。
3. **停在正体揭示之前** — 歌词与说明尊重 series-bible 的披露程度。走到机关为止，不唱正体 · 结局。
4. **克制也延及歌词** — 歌词遵循同一流露与克制。不解释主题，不点名情感，留出听者的留白。唱「这是关于◯◯的故事」的副歌，已经点名了。

## 歌词是要被「唱」出来的话（craft）

歌词不是散文的行。它是为被声音承载而写:

- **音节数与节奏** — 能上旋律的行，可分拍。
- **押韵与重复** — 副歌靠重复留存。是听一遍就该留下的一行。
- **副歌是钩子** — 如同宣传语，不点名地承载主题。
- **歌词这个媒介特有的危险** — 行越短，解释与点名越显眼。歌词比散文更无处藏身，所以克制更要，而非更松。

## 读法安全版（混合版 · 第二份歌词）

音乐生成器不是**读**歌词，而是**发出**歌词。读错的一个字，会成为唱出来的那个词，听者再也无法还原那行。所以 theme-song 交出**两份歌词**:

- **歌词** — `theme-song.md`（或有名字的版本），保持作品的写法。这是正本。
- **读法安全版（混合版）** — `theme-song-mix.md`（若歌词来自有名字的版本，就在那个名字旁加 `-mix`——如 `theme-song-rock-mix.md`）。同一份歌词，只把**有读错危险的词**展开为假名（日语歌词；其他语言则按该语言的危险固定读音）。

混合版**不是改写**。词、行、顺序、结构标签、唱出的音节都相同。变的只是危险词的**写法**。混合版是与正本对听的**第二个候选**，不是对正本的订正，也不是第七个交付物——它是同一份歌词的第二种写法。

### 适度——只展开最小限度

只在**存在实际失败形态**时展开一个词。

| 危险 | 例（日语歌词） |
|---|---|
| 读法分裂 | 設計（せっけい／せつけい）· 保守（ほしゅ／まもり）· 半分（はんぶん／はんぷん）· 開く（ひらく／あく）· 月曜日（げつようび／つきようび——び 可能脱落）· 方（かた／ほう）· 親（おや／しん）· 鍵（かぎ／けん） |
| 生僻复合词 · 长复合词 · 词典外的词 | 冪等性 · 枯渇 · 扇風機 · 環境変数 · 消費電力 · 先週 |
| 数字 · 时刻 | 500 → ごひゃく · 十九 → じゅうきゅう · 三百五十三 → さんびゃくごじゅうさん · 二時 → にじ |
| 拉丁缩写 · 符号 | CPU · SLO · I/O · .env |
| 没有语境的短行 | 只有一个词的行、前后不提供语法的行 |
| 读法改变意思的词 | 開いた（あいた／ひらいた） |
| 耳朵不能错的钩子 | 主题词、歌发生转折的那一行 |

钩子可以只展开一部分——保留主题词的字面，只展开危险的那个字（揺れ方 → 揺れかた）。

以下情况保留汉字:

- **送假名固定了读法** — 読まない · 知らない · 冷たい · 割り込み。活用形只有一种读法。
- **在这个语境里只有一种读法** — 部屋 · 画面 · 光 · 声 · 指。せい · こう · し 在这里不是词。
- **字面在承载意思** — 主题词、曲名、一字的转折（来るな → 来た）、展开后会与同音异义词相撞的词（二本 → にほん ＝ 日本）。
- **片假名外来语** — 展开成平假名反而不自然。可以展开的只到拉丁缩写，且写成片假名（CPU → シーピーユー）。
- **展开会抹掉断词的线索。** 假名的边界不是免费的: 假名越多，生成器能听出的词边界越少。

**拿不准时，保留汉字，把它放进「若仍听错」的表。** 下一轮只展开真正听错的词。

### 日语以外的歌词

同一原则，对准该语言自己的危险:

- **中文** — 多音字、生僻复合词、阿拉伯数字、拉丁缩写。用空格切开有歧义的复合词，把数字和缩写写成词，只在意思不变时换成同音安全的词。拼音消歧放在歌词栏外的表里——生成器会照写出来的唱。
- **英文** — 同形异音词（read／read · live／live · lead／lead）、缩写、数字、专有名词。把数字和缩写展开成词；只在行仍成立时，把同形异音词换成无歧义的词。不要把发音拼写放进歌词栏——那会被照原样唱出。

### 混合版的规则

1. **只改读音** — 不换同义词、不增删行、不调顺序、不改结构标签。
2. **正本仍是正本** — 混合版不覆盖它。两个文件互相指向。
3. **一次一个** — 不要把两份同时贴进生成器。Style · Vocal · Exclude · 时长保持一致，只换 Lyrics 栏。
4. **曲名不动** — 曲名保持作品写法。若展开副歌钩子（揺れ方 → 揺れかた），要写明，并给出「保留曲名写法、接受读错」的选择。
5. **标明这是假说** — 生成之前，混合版未被验证。文件写明展开了哪些词、保留了哪些词、听什么（读音 · 断句 · 旋律）、怎么选（各完整听一遍；两份都错就全假名，或展开下一张表）。

### 混合版文件里放什么

1. **出处与范围** — 从哪份歌词而来，改的只是写法。
2. **假说标记** — 「尚未试过」，以及关于生成器如何读错的判断。
3. **歌词栏** — 可直接粘贴，结构标签相同。
4. **展开的词** — 表: 词 → 展开形 → 为什么（失败形态）。
5. **保留汉字的词（边界桩）** — 保留的理由。
6. **「若仍听错」** — 听到的读音 → 下一步展开的形。
7. **怎么比较** — 同样条件、一次一个、听读音 · 断句 · 旋律。
8. **弱点** — 残留的危险、假名边界的代价、失去的字面。

## 一个灵魂，两扇门

主题曲与 package 是通向同一灵魂的两扇门，不是两个灵魂。若 `package.md` 已存在，曲名 · 副歌 · 曲风必须与 package 的标题 · 宣传语 · 简介一致——承诺 · 调子 · 声音相同。

## 步骤

1. 读 draft.md · premise.md（主题 · 核心问句）· series-bible.md（披露程度）· persona（声音）· package.md（若有）。
2. 俯瞰作品整体——主题 · 结构 · 情感升起的场景 · 正体揭示——然后决定歌所唱的「那一个瞬间」。主题曲是灵魂的一瞬，不是梗概的提要。
3. 引出歌的核心那一行（不点名地承载主题的钩子）。以下一切都从这里导出。
4. 按序写出六个交付物：曲名 → 歌词（结构标签）→ 曲风指定 → 声乐 → 歌曲说明 → 位置与意图。
5. 写出读法安全版——只展开有实际失败形态的词，其余的词、行、标签原样保留，并记录展开了什么、保留了什么，以及「若仍听错」的表。
6. 逐条对照四则检验：不撒谎地唱 · 承诺真正交付的 · 停在正体揭示之前 · 克制也延及歌词。
7. 以「一个灵魂，两扇门」检验整体——与 package 是否朝同一部作品敞开。
8. 保存 `<工作目录>/theme-song.md` 与 `<工作目录>/theme-song-mix.md`。

## 输出

- `<工作目录>/theme-song.md` —— 歌曲一套（曲名 / 歌词 / 曲风指定 / 声乐 / 歌曲说明 / 位置与意图），并附一行指向 `theme-song-mix.md` 的说明。
- `<工作目录>/theme-song-mix.md` —— 读法安全版（歌词栏 · 展开的词 · 保留汉字的词 · 「若仍听错」的表 · 比较方法 · 弱点）。若在有名字的版本旁，就随那个名字命名（`<版本名>-mix.md`）。若歌词本来就全部是假名、没有残留的危险词，则在 `theme-song.md` 中写明，不创建此文件。

## 注意

- **依据是作品的灵魂——主题与情感升起的场景——不是读者的第一印象。** 面向读者是 package 的事；歌面向灵魂。
- **series-bible 的披露程度是边界。** 不唱正体 · 结局。
- **歌词是作品之声入歌，不是营销。** 是把作品的灵魂压进可唱的几行。
- **歌词用作品的语言，曲风指定用英语标签。** `lang` 参数只改变技能自身的散文。
- **过度解释的歌词，已经破了第五则（不道破源）。** 行越短，越要克制。
- **混合版改的是声音，不是词。** 它是第二个候选，不是订正。正本是出处文件（`theme-song.md`，或有名字的版本）里的歌词。
- **只展开最小限度。** 展开太多，生成器赖以断词的边界会消失——只是把读错的危险换成了断句的危险。
- **曲名保持作品写法。** 可以展开的只到歌词的钩子，且必须在混合版文件里写明。
