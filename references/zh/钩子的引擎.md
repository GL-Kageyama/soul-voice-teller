# 钩子的引擎（hook-engine）

## ― 是什么让读者翻页：未知 × 想知道 ―

「好想知道接下来会怎样（続きが気になる）」不是六种反应之一，而是所有六轴赖以运转的**引擎**。作品可以乘任何一种轴——惊叹・幽默・感动・快乐・恐惧・可爱——但一旦引擎熄灭，读者就会离开。本文件把 [six-response-axes.md](../six-response-axes.md) 中的一句话——「兴趣是引擎，而非轴」——展开为钩子的三部分设计。

## 1. 钩子的本质 — 未知 × 想知道

钩子 = **未知** × **想知道**。两个项，缺一不可。

- **未知** — 读者尚不知道、也无法预料的东西。
- **想知道** — 读者*在意*到愿意去合上那道缺口。

只有其一都不成其为钩子。读者不在意的未知只是噪音。没有未知的想知道是满足——故事到此也就结束了。

在此分岔的两种失败模式：

- **只有载体（器だけ）** — 存在未知，但没有想知道（那道缺口没有接到读者已握有的东西上）。
- **无聊（退屈）** — 一切都可预料，根本不存在未知。

## 2. 载体 — 先给予，再残缺（给 → 缺）

未知必须栽在读者已经握有的东西上。那东西就是**载体（器）**——角色、场景、特殊设定。载体的魅力是六轴（[six-response-axes.md](../six-response-axes.md)）；钩子借那些反应的*敞开的一半*作燃料（§4）。

手法始终如一：**先给予，再残缺（与える → 欠けさせる）**。

1. **给予（与える）** — 让读者*拥有*某物：羁绊（絆）、形象（像）、信任的承诺（信頼）。拥有是在意的前提。
2. **残缺（欠けさせる）** — 让它变得不完整：夺走、隐藏、置于危险。

钩子的强度就是拥有的强度。想知道依附于读者已经安顿下来的东西——羁绊、形象、被信任的承诺。这种依附就是**转移（乗り移り）**：读者的想知道驰骋于絆 / 像 / 信頼之上。

## 3. 配置 — 连锁的四轴

钩子不是单个瞬间，而是**连锁**。贯穿全作的疑问是**主干（幹）**——必须保住到顶点的整体钩子。场面的疑问是**枝干（枝）**——一页一页载着读者前行的小钩子。两者沿四轴咬合：

| 轴 | 它回答的问题 | 它的失败模式 |
|---|---|---|
| 承接（継ぎ） | 当一个答案落地，它是否开启下一个疑问？ | 断线（断線）——没有下一个疑问的答案 |
| 推进（進み） | 每个枝干的答案是否推进主干？ | 拖延（先送り）——永不靠近主干的枝干答案 |
| 间距（間合い） | 间隔是否与疑问的大小相称？ | 太迟／搁置（遅すぎ／放置）——疑问在得到回答之前就被遗忘 |
| 保留（温存） | 主干是否被保住到顶点？ | 太早（早すぎ）——开头就给出主干的答案（兴趣的终结） |

疑问的生命周期——立起（立てる）→ 保持（保つ）→ 应答（応える）→ 接续（継ぐ）——在这四轴上运转。主干走得慢，枝干走得快：间隔与疑问的大小相称。

## 4. 六轴敞开的一半

钩子是**六轴的反应，被冻结在其敞开的一半**。惊叹的超脱、感动的同一化、恐惧的庇护——在它们*闭合*（信服・宣泄・安心）之前，它们*牵引*（「为什么？」「会怎样？」「能得救吗？」）。钩子借那股敞开的、未决的力量，把它的「为什么？」转化为引擎。当反应终于闭合，敞开的一半得以完成——成为六轴所命名的闭合反应。

## 技能如何使用此原则

- **premise** — 主干：核心问题与承诺（信任路径）就是整体钩子。
- **plot-design** — 配置：场面表分配抓住・保持・释放，并把主干的答案保留到顶点。
- **准备工作（character-forge / character-bond / worldbuild）** — 载体：在此打造载体（其魅力＝六轴）。
- **fast-draft / scene-writer** — 执行：逐场「先给予，再残缺」。
- **entertainment** — 检视引擎，补足薄弱的兴趣之轴。
- **revise-for-reader / whole-work-review** — 确认承接与保留是否落地、主干是否保全到最后。
