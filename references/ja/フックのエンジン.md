# フックのエンジン（hook-engine）

## ― 読者にページをめくらせるもの：未知 × 知りたさ ―

「続きが気になる」は6つの反応のひとつではない。6つの軸すべてを走らせる**エンジン**である。作品はどの軸に乗ってもよい——感嘆・ユーモア・感動・楽しい・恐怖・かわいい——が、エンジンが死んだら、読者は離れる。このファイルは [six-response-axes.md](../six-response-axes.md) の一言——「興味はエンジンであり、軸ではない」——を、フックの三部構成の設計へ展開する。

## 1. フックの正体 — 未知 × 知りたさ

フック = **未知** × **知りたさ**。二つの項、どちらも必須である。

- **未知** — まだ読者が知らず、予測できないもの。
- **知りたさ** — その隙間を「閉じたい」と読者が*気にかける*こと。

どちらか一方だけではフックにならない。読者が気にしない未知はノイズである。未知のない知りたさは充足——そこで物語は終わる。

ここで分かれる二つの失敗モード：

- **器だけ** — 未知はあるが、知りたさが無い（その隙間が、読者が手にしたものに繋がっていない）。
- **退屈** — すべて予測通りで、未知が無い。

## 2. 器 — 与える → 欠けさせる

未知は、読者が既に手にしたものに植えられなければならない。そのものこそ**器**——キャラクター・場面・特殊設定。器の魅力は6軸（[six-response-axes.md](../six-response-axes.md)）であり、フックはその反応の*開きの半身*を燃料として借りる（§4）。

手はいつも同じ：**与える → 欠けさせる**。

1. **与える** — 読者に*所持*させる：絆・像・信頼。所持こそが気にかける前提である。
2. **欠けさせる** — それを不完全にする：奪う・隠す・危険に晒す。

フックの強さは、所持の強さである。知りたさは、読者が身に馴染ませたもの——絆・像・信頼の約束——に取り憑く。この取り憑きが**乗り移り**である：読者の知りたさは絆・像・信頼の上を走る。

## 3. 配置 — 連鎖の4軸

フックは単発の瞬間ではなく**連鎖**である。作品全体の問いは**幹**——頂点まで保たれねばならない全体フック。場面の問いは**枝**——ページごとに読者を運ぶ小さなフック。両者は四つの軸で噛み合う：

| 軸 | それが答える問い | その失敗モード |
|---|---|---|
| 継ぎ | 答えが着地したとき、次の問いを開くか | 断線 — 次の問いの無い答え |
| 進み | 枝の答えは幹を進めるか | 先送り — 幹に近づかない枝の答え |
| 間合い | 間隔は問いの大きさに比例するか | 遅すぎ／放置 — 答えより先に問いが忘れられる |
| 温存 | 幹は頂点まで保たれるか | 早すぎ — 幹の答えを冒頭で出す（興味の終了） |

問いのライフサイクル——立てる → 保つ → 応える → 継ぐ——はこの四つの軸の上を走る。幹は遅く、枝は速く：間隔は問いの大きさに比例する。

## 4. 6軸の開きの半身

フックとは**6軸の反応を、開きの半身で凍結したもの**である。感嘆の超出、感動の同一化、恐怖の庇護——それらが*閉じる*（納得・カタルシス・安心）前、*引っ張る*（「なぜ？」「どうなる？」「助かる？」）。フックはその開いた未決の力を借り、その「なぜ？」をエンジンへ変換する。反応がようやく閉じたとき、開きの半身は完成する——6軸が名付ける閉じた反応へ。

## スキルはどう使うか

- **premise** — 幹：core question と約束（信頼経路）が全体フックである。
- **plot-design** — 配置：scene table が grab・hold・release を配り、幹の答えを頂点まで温存する。
- **下準備（character-forge / character-bond / worldbuild）** — 器：ここで器を作る（その魅力＝6軸）。
- **fast-draft / scene-writer** — 実行：場面ごとに与える→欠けさせる。
- **entertainment** — エンジンを検品し、弱い興味の軸を補う。
- **revise-for-reader / whole-work-review** — 継ぎと温存が着地したか、幹が最後まで保たれたかを確かめる。

厚い方法論（正体・器・配置・失敗モード）は `資料/物語のフック構想/` にある。このファイルは、引用のための薄い原則である。
